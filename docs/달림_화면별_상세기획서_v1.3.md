# PART 0. 진단 — 원문에서 비어 있는 12가지

원문은 **"무엇을 만들 것인가"** 는 매우 잘 정의되어 있습니다. 그러나 **"어떻게 유지되고, 어떻게 돈이 되는가"** 는 P3로 밀려 있어 화면 설계에 훅이 하나도 없습니다.

| # | 빈 구간 | 왜 치명적인가 | 이 문서에서의 보완 |
|---|---|---|---|
| 1 | 수익화가 마지막(P3) | 수익 훅은 나중에 "붙이는" 게 아니라 화면에 **심어두는** 것. 달림북·공유카드·완주화면은 이미 최고의 지불 지점인데 비어 있음 | PART 1 수익 구조 재설계 + 각 화면 `💰` 훅 |
| 2 | 온보딩 화면 없음 | 가입 → **첫 달림 완주**까지가 이 서비스의 전부. 여기서 90% 이탈 | S-01~S-06 |
| 3 | 기본 거리 5km | 러닝 미경험자에겐 진입 불가. "그림 러닝"의 타깃은 기록러너가 아니라 **러닝 라이트 유저** | 1.5~3km 미니 스케치 도입 |
| 4 | 부정행위(치팅) 대응 없음 | 자전거·차량으로 그림 완성 가능. **보상·유료 챌린지가 붙는 순간 서비스 붕괴** | PART 4 부정행위 판정 |
| 5 | UGC 모더레이션 없음 | 직접 그리기 = 사용자 생성 콘텐츠. 음란·혐오 형태, 브랜드 로고, 사유지·위험도로 통과 | PART 4 모더레이션 |
| 6 | 푸시/알림 설계 전무 | 러닝앱은 **날씨·시간대 트리거**가 리텐션의 절반 | PART 4 알림 매트릭스 |
| 7 | 빈 상태(Empty) 설계 없음 | 지방·신규 지역에서 앱을 열면 텅 빔 → 즉시 삭제 | 모든 화면 `상태` 항목 |
| 8 | 성장 루프 없음 | 공유카드는 있는데 **딥링크·초대코드·역유입 화면**이 없어 K값 0 | S-26, S-70 |
| 9 | 지역 콜드스타트 | 소셜 세션은 밀도가 없으면 100% 실패 | PART 5 거점 도시 전략 |
| 10 | 안전이 "원칙"으로만 존재 | 여성 사용자 확보 실패 = 서비스 실패. 화면이 있어야 신뢰됨 | S-64~S-67 |
| 11 | 법무 체크리스트 없음 | 위치기반서비스 신고, 개인정보 국외이전(Supabase 리전), 인앱결제, 실물 배송 시 전자상거래법 | PART 6 |
| 12 | 성공 지표(KPI) 없음 | MVP1 "성공 기준"이 정성적("달릴 수 있어야 한다")뿐 | PART 7 |

### 기술 스택 — 1인 개발 기준 코멘트

Kotlin 통일(Ktor + Android)은 도메인 모델·검증 로직을 그대로 공유할 수 있어 **혼자 만들 때 오히려 이점이 큽니다.** 다만 1인 개발에서 진짜 병목은 언어가 아니라 **서버에서 직접 조립해야 하는 것들**(인증, 소셜 로그인, 파일 스토리지, 실시간 채팅, 스케줄러, 푸시)입니다.

권장 분담:

```text
Supabase가 담당   Auth / Storage / Realtime(팀 채팅) / PostGIS
Ktor가 담당        코스 생성·검증, 완주 판정, 러닝온도, 보상, 결제 검증
배치/스케줄러      대회 정보 수집, 시즌 컬렉션 오픈, 주간 리포트 푸시  ← v1.1 추가
```

핵심은 **"서버는 얇게, 클라이언트는 두껍게"**. 안드로이드 + 백엔드를 혼자 하는 이상, 백엔드에서 직접 만드는 코드가 늘수록 출시는 기하급수적으로 멀어집니다.

> **참고(달림 프로젝트 실제 스택 결정, 2026-08-24)**: 위 권장안의 Supabase 분담은 실제로는 채택하지 않았고, Auth/Storage/PostGIS를 포함해 백엔드는 전부 Ktor + Exposed + PostgreSQL(PostGIS) + Redis로 자체 구현했다(`CLAUDE.md` 참고). Realtime(팀 채팅)이 필요한 소셜 세션(S-30~S-39)은 여전히 범위 밖이라 이 결정이 재검토된 적은 없다.

# PART 1. 수익 구조 재설계 — "구독"이 아니라 "완성된 작품"을 판다

원문의 수익 모델은 `AdMob + RUN+ 구독` 2단입니다. 둘 다 **러닝앱에서 가장 안 팔리는 조합**입니다. 광고 CPM은 낮고, 구독은 이미 Nike Run Club(무료)·Strava와 경쟁해야 합니다.

달림에만 있는 **지불 의사 지점**은 따로 있습니다.

> 사용자가 5km를 달려서 GPS로 고래를 완성했다.
> 이 순간 사용자는 **기록**을 얻은 게 아니라 **작품**을 얻었다.
> 작품에는 (a) 자랑하고 싶고 (b) 남기고 싶고 (c) 인증받고 싶은 욕구가 붙는다.

### 수익 우선순위 (권장)

| 순위 | 모델 | 근거 | 붙는 화면 |
|---|---|---|---|
| **1** | **유료 챌린지 / 버추얼 레이스** | 러너는 이미 마라톤 참가비를 지불하는 습관이 있음. "완주 메달 + GPS 그림"은 기존 버추얼 레이스보다 인증샷 경쟁력이 높음. **선결제 → 후발송**이라 현금흐름이 가장 빠름 | S-52, S-53 |
| **2** | **실물 굿즈(POD)** — GPS 그림 포스터·티셔츠·아크릴 키링 | 완주 직후 감정 최고점에서의 충동구매. 재고 0(주문제작), 마진 확보 용이 | S-25, S-41, S-54 |
| **3** | **B2B 스폰서 코스** — 지자체 관광과, 러닝 브랜드, 상권 | "우리 도시를 달려 캐릭터를 완성하세요"는 지자체 관광 예산과 정확히 맞는 상품. **브랜드 로고 모양 코스**는 달림만 가능한 광고 지면 | S-55 |
| 4 | RUN+ 구독 | 헤비 유저 대상 보조 수익. 단독으로는 규모가 안 나옴 | S-50 |
| 5 | 광고(AdMob) | 초기 매출 기여 미미. **리워드형 기능 체험**으로만 사용(원문 방향 유지) | S-56 |

> ⚠️ 위 순위는 시장 가정에 기반한 **기획 판단**이며, 실제 단가·전환율은 거점 도시 1곳에서 검증 후 확정해야 합니다.

### 수익화 3원칙 (화면 설계 시 절대 규칙)

1. **달리는 행위 자체는 영원히 무료.** 거리 제한·코스 제한·기록 제한 금지.
2. **결제는 "달린 뒤"에만 제안한다.** 달리기 전 페이월은 이탈만 만든다.
3. **안전·신뢰 기능은 절대 유료화하지 않는다.** (Safety Share, 신고, 이탈 복귀)

# PART 3. 화면별 상세 기획

각 화면은 아래 템플릿을 따릅니다.
`목적 / 진입 / 구성요소 / 상태(로딩·빈·에러) / 액션 / 예외 / 💰수익훅 / 📊로그`

## A. 온보딩 & 인증 (S-00 ~ S-06)

> **이 구간의 유일한 목표: 설치 후 24시간 내 첫 GPS 그림 1개 완성.**
> 원문에 통째로 빠져 있던 구간이며, 리텐션의 80%가 여기서 결정됩니다.

### S-00 스플래시

- **목적**: 세션 복원 및 최소 로딩
- **구성요소**: 로고 애니메이션(GPS 선이 그려지며 로고 완성 — 1.2초), 버전
- **상태**: 토큰 유효 → S-10 / 무효 → S-01 / 강제 업데이트 필요 → 업데이트 모달(닫기 불가)
- **예외**: 서버 점검 시 점검 안내 화면(예상 종료 시각 표기)

### S-01 가치 제안 (신규)

- **목적**: "러닝앱"이 아니라 "**그림을 달리는 앱**"임을 3초 안에 각인
- **구성요소**: 3장 캐러셀, 각 장은 **실제 GPS 그림 애니메이션**이 그려지는 모션
  1. `길 위에 그림이 숨어 있어요` — 지도 위 고래 경로가 그려짐
  2. `달리면 그림이 완성돼요` — GPS 트레이스가 채워짐
  3. `내 작품을 모으세요` — 달림북 그리드가 채워짐
- **액션**: [시작하기] / 하단 [이미 계정이 있어요]
- **핵심**: 스킵 버튼을 우상단에 두되, **3번째 장은 자동 넘김 금지**(달림북 = 수집 동기를 반드시 노출)
- 📊 `onboarding_slide_view(index)`, `onboarding_skip(index)`

### S-02 로그인

- **구성요소**: Google 로그인(1순위), Kakao(2순위 — 국내 필수, 원문 "추후"에서 **MVP1로 상향 권장**), 이메일(최후)
- **상태**: 로딩 중 버튼 비활성 + 스피너 / 실패 시 인라인 에러(계정 선택 취소는 에러 아님)
- **예외**: 동일 이메일 다른 provider 가입 이력 → 계정 통합 안내 모달

### S-03 약관 동의

- **구성요소**: 전체 동의 / 이용약관(필수) / 개인정보처리방침(필수) / **위치기반서비스 이용약관(필수)** / 마케팅 수신(선택) / 만 14세 이상(필수)
- **핵심**: 각 항목 우측 [보기]로 전문 진입. 필수 미동의 시 [다음] 비활성
- **법무**: 위치정보 항목은 별도 동의로 분리(묶음 동의 불가)

### S-04 프로필 설정

- **구성요소**: 닉네임(중복검사, 2~10자, 금칙어 필터), 아바타 기본 6종 선택, 러닝 경험 5단계, 편안한 페이스 6단계, 성별(**비공개 저장** 안내 문구 필수 노출)
- **성별 입력 옆 고정 문구**: `성별은 다른 사용자에게 절대 표시되지 않아요. 세션 참가 조건 확인에만 사용돼요.`
- **상태**: 닉네임 중복 → 인라인 에러 + 추천 닉네임 3개 제시
- 📊 `profile_complete(experience, pace)`

### S-04b 러닝 커리어 입력 (신규 · 선택 · 조건부 노출)

- **노출 조건**: S-04에서 러닝 경험을 `1~3년` 또는 `3년 이상`으로 선택한 경우에만
- **목적**: 오래 달려온 사람에게 **"이 앱은 초보용 장난감이 아니다"** 라는 신호를 즉시 주는 것. 경력 러너는 온보딩에서 자기 커리어를 넣을 곳이 없으면 앱을 가볍게 봅니다
- **구성요소**
  - `대회에 참가해보신 적 있나요?` [있어요] / [아직 없어요]
  - 있음 → 간이 입력 1건: 대회 검색(DB) → 종목(5K·10K·하프·풀·울트라·트레일) → 연도 → 기록(선택)
  - `나중에 더 추가할 수 있어요` 안내 + [건너뛰기] 항상 노출
- **자동 처리**: 하프·풀 기록 입력 시 **예상 편안한 페이스 자동 계산 → S-04 페이스 값 제안**(사용자 확인 후 반영)
- **연결**: 입력 즉시 S-82 메달 선반에 첫 카드 생성 → 온보딩 직후 "이미 뭔가 쌓여 있는 상태"를 만듦
- 📊 `career_entry_shown`, `career_entry_add(event, distance, has_record)`

### S-05 권한 요청 (신규 — 원문 누락, 안드로이드 필수)

- **목적**: 권한 거부로 인한 GPS 기록 실패를 **사전 차단**
- **순서 및 사전 설명(Priming) 화면 필수**:
  1. **위치(정확한 위치, 앱 사용 중)** — `달리는 길을 그림으로 남기려면 위치가 필요해요`
  2. **백그라운드 위치** — 첫 러닝 시작 직전(S-20)에 요청 ⚠️ *온보딩에서 요청하면 거부율 급증*
  3. **알림** — `세션 시간과 오늘의 그림을 알려드릴게요`
  4. **배터리 최적화 제외** — S-20에서 안내(삼성/샤오미 기기 대응 가이드 링크 필수)
- **상태**: 거부 시 앱을 막지 않음. 홈 상단에 **복구 배너** 상시 노출(`위치 권한이 없어 달리기를 기록할 수 없어요 [설정 열기]`)
- **예외**: "다시 묻지 않음" 2회 거부 → 시스템 설정 딥링크로만 유도
- 📊 `permission_result(type, granted)` — **권한별 허용률은 최상위 모니터링 지표**

### S-06 첫 코스 제안 (신규 — 가장 중요한 온보딩 화면)

- **목적**: 온보딩 마지막에 **"지금 나갈 수 있는 코스" 1개**를 던져 첫 달림까지 거리를 0으로 만듦
- **구성요소**:
  - 현재 위치 기준 **1.5~2.5km 미니 스케치 1개** (예: `🐟 물고기 · 1.8km · 약 14분`)
  - `처음이라면 이 정도면 충분해요` 카피
  - [지금 달리기] (Primary) / [나중에 할게요]
- **핵심 설계**: 원문 기본값 5km는 러닝 미경험자에게 **진입 불가 수준**입니다. 온보딩 코스는 **거리 ≤ 2.5km, 신호등 ≤ 3개, 왕복 없는 루프**로 강제 필터링합니다.
- **상태(빈)**: 주변 도로 데이터 부족 → `아직 이 지역엔 발견된 그림이 적어요` + [직접 그려보기] + 지역 등록 요청 버튼(콜드스타트 지역 수집)
- 📊 `first_course_offered(distance)`, `first_run_start_from_onboarding`

## B. 홈 & 코스 탐색 (S-10 ~ S-17)

### S-10 홈

- **목적**: 열자마자 **오늘 달릴 이유** 제공. 정보 나열이 아니라 **하나의 결정**을 유도
- **구성요소 (위→아래 우선순위)**

  1. **상단 상태 바**: 날씨 + 러닝 적합도 (`오늘 22°, 달리기 좋아요`) ← 신규 제안. 러닝앱 리텐션 최대 트리거
  1-1. **목표 대회 D-day 스트립** (목표 대회 설정 시에만 노출): `🏅 서울 하프 D-42 · 이번 주 8/20km` → S-82
      ⭐ 목표 대회가 있는 유저는 없는 유저보다 러닝 빈도가 확연히 높습니다. **이 한 줄이 홈에서 가장 강한 리텐션 장치**가 될 수 있습니다.
  2. **오늘의 달림 (Hero 카드)**: 🐳 고래 / 5.1km / 예상 36분 / Sketch Match 92% / [코스 보기]
  3. **이어서 달리기**: 최근 저장 코스 or 미완주(PARTIAL) 코스 재도전 유도
  4. **내 주변 함께 달리기**: 가로 스크롤 세션 카드 (있을 때만)
  5. **진행 중 미션**: 주간 미션 진행률 바 1개만
  6. **최근 달림**: GPS 썸네일 3개 가로 스크롤
  7. (선택) Native Ad — **5번째 블록 아래에만**
- **상태**
  - 로딩: 스켈레톤(Hero 카드 형태 유지)
  - **빈(신규 유저)**: 오늘의 달림 + [내 주변 그림 찾기] 2개만 노출. 나머지 블록 숨김
  - **빈(비활동 지역)**: 세션 블록 자체를 숨기고 `이 지역 첫 번째 러너가 되어보세요` CTA
  - 오프라인: 캐시된 최근 달림 + `오프라인 상태예요` 배너 (달리기 기능은 정상 동작해야 함)
- **액션**: 카드 탭 → S-16 / 하단 탭 이동
- 💰 RUN+ 미구독자 중 **3회 이상 완주자**에게만 주 1회 상단 슬림 배너 노출(그 외 노출 금지)
- 📊 `home_view`, `home_block_impression(block, index)`, `home_card_tap(type)`

### S-11 탐색 (코스 / 세션 / 챌린지 통합)

- **구성요소**: 상단 세그먼트 `[그림 코스] [함께 달리기] [챌린지]`, 지도/리스트 토글, 필터 시트
- **필터**: 거리(1·3·5·10km·직접입력), 난이도, 신호등 적음, 평지, 반복 적음, 상태(DISCOVERY/VERIFIED/POPULAR), 정렬(인기·가까운·새로운)
- **카드 구성**: GPS 형태 썸네일(**아이콘 금지, 실제 경로 실루엣**), 이름 + 이모지, 거리/예상시간, 완주자 수 배지, DISCOVERY는 `아직 아무도 달리지 않음` 태그
- **상태(빈)**: 반경 확대 제안(`3km 내에 없어요 → 10km로 넓혀볼까요?`) → 그래도 없으면 [AI로 찾기] / [직접 그리기]
- 💰 정밀 필터(평지·신호·반복)는 RUN+ 전용 → 잠금 아이콘 탭 시 S-50. **단, 거리 필터는 무료**
- 📊 `explore_filter_apply(filters)`, `explore_empty(radius)`

### S-12 AI Sketch Discovery — 입력

- **구성요소**: 위치(현재 위치 / 지도에서 선택 / 검색), 목표 거리 슬라이더(1~15km), 옵션 칩(평지·신호등 적게·반복 적게·계단 회피·시작=도착), 남은 무료 탐색 횟수 표시
- **핵심 카피**: `그림을 고르는 게 아니라, 길에서 그림을 찾아드려요`
- **상태**: 일 무료 횟수 소진 → `[광고 보고 1회 더]` / `[RUN+로 무제한]` 2지선다 모달
- 💰 무료 3회/일 · 광고 리워드 +2회 · RUN+ 무제한 (숫자는 검증 후 조정)
- 📊 `discovery_request(distance, options)`, `discovery_quota_hit`

### S-13 Discovery — 결과

- **목적**: 후보 비교가 아니라 **"이거다" 하나 고르기**
- **구성요소**: 카드 스택(스와이프) 3~5개 / 각 카드: 지도 미리보기 + 형태 오버레이, `🐳 고래 93%`, 거리, 예상시간, Runability 뱃지
- **하단**: [이 코스로 달리기] / [다시 찾기] / [저장]
- **상태**
  - 생성 중: `길을 뒤지는 중...` 진행 단계 3스텝 노출(도로망 → 후보 생성 → 형태 분석). **10초 이상 걸리면 이탈**하므로 단계 시각화 필수
  - 실패: `이 지역에선 그림을 찾기 어려웠어요` + 거리/옵션 완화 제안 버튼
- **중요 보완**: **"무엇처럼 보이는지 모르겠음"** 결과도 정직하게 노출(`이름 없는 코스 — 당신이 이름을 붙여주세요`). 억지 라벨링은 신뢰를 깎습니다. 이게 오히려 S-16 커뮤니티 투표의 콘텐츠가 됩니다.
- 💰 후보 +3개 = 리워드 광고 / RUN+
- 📊 `discovery_result(count, top_score)`, `discovery_select(rank)`

### S-14 직접 그리기 (캔버스)

- **구성요소**: 전체화면 지도, 하단 툴바(그리기·지우개·되돌리기·다시실행·전체삭제), 시작점 핀 드래그, 실시간 예상 거리 표시(**그리는 동안 상단에 `약 4.2km` 갱신** — 원문 누락)
- **제스처 충돌 해결(원문 누락)**: 기본은 **지도 이동 모드**, [✏️ 그리기] 토글 시에만 드로잉. 그리기 모드에서 두 손가락은 줌으로 예외 처리
- **상태**: 획이 너무 짧음(<300m) → [변환] 비활성 + 안내 / 획이 도로 없는 곳(강·바다·산) → 해당 구간 빨강 표시
- **모더레이션**: 변환 요청 시 서버에서 형태·이름 검수 큐 등록 (PART 4 참조)
- 📊 `draw_start`, `draw_undo_count`, `draw_convert_request(length)`

### S-15 그리기 → 실제 코스 변환 결과

- **구성요소**: 상단 **원본 vs 실제 경로 오버레이**(원본=점선 회색, 실제=실선 강조), 큰 숫자로 `Sketch Match 87%`
- **3후보 탭**: `[모양 우선] [달리기 편함] [목표 거리]` — 탭 전환 시 지도 즉시 갱신
- **액션**: [이 코스로 달리기] / [다시 그리기] / [저장]
- **상태(실패)**: 매칭 불가 → `그린 모양이 도로와 너무 달라요` + 자동 단순화 제안(`선을 조금 단순하게 만들어 볼까요?`)
- 💰 3후보 동시 비교(Route Compare)는 **1일 1회 무료 → 이후 광고/RUN+**
- 📊 `convert_result(match, candidate_type)`

### S-16 Route 상세

- **목적**: 이 화면의 성공 = **[달리기] 전환율**. 정보량이 아니라 결정을 돕는 순서로 배치
- **구성요소**
  - 상단 지도(형태 강조, 스크롤 시 축소 고정)
  - 이름 + 이모지 + **커뮤니티 투표 상태**(`고래 73% · 물고기 19%` / [나도 투표])
  - 상태 뱃지: DISCOVERY / VERIFIED(`12명 완주`) / POPULAR(`148명 완주`)
  - **First Discoverer 슬롯**: 미달성 시 `🏅 아직 최초 완주자가 없어요` ← 강력한 행동 유도. 달성 시 해당 유저 아바타+닉네임
  - 스펙 그리드: 거리 / 예상시간 / 난이도 / Sketch Match / 신호등 수 / 누적 고도 / 반복 구간 / Runability
  - 러너 평가 태그 상위 3개(`그림이 잘 보여요 · 신호가 많아요`)
  - 이 코스를 달린 사람들의 GPS 결과 썸네일 가로 스크롤 ← **사회적 증거이자 최고의 재도전 유도**
- **하단 고정 CTA**: [혼자 달리기](Primary) / [같이 달리기](Secondary) / 저장·공유 아이콘
- **상태(안전)**: 야간(일몰 후) 진입 시 `이 코스는 가로등 정보가 없어요. 밝은 시간대를 추천해요` 배너
- 💰 스폰서 코스인 경우 상단에 `[함께하는 브랜드]` 표기 + 완주 리워드 안내 (S-55)
- 📊 `route_detail_view(route_id, status)`, `route_run_start(mode)`

### S-17 저장한 코스

- **구성요소**: 저장 코스 그리드 / 정렬(최근·거리·미완주) / **미달림 코스 상단 고정**
- **핵심 보완**: `저장했지만 아직 안 달린 코스`가 3개 이상이면 홈에서 리마인드 푸시 대상으로 전환
- **상태(빈)**: `마음에 드는 코스를 저장해두면 여기 모여요` + [코스 찾기]

## C. 달리기 (S-20 ~ S-27) — **P0 중의 P0**

> 이 6개 화면만 완벽해도 서비스는 성립합니다. 반대로 여기가 흔들리면 나머지는 전부 무의미합니다.

### S-20 러닝 준비 (Pre-Run)

- **목적**: 달리기 시작 전 **실패 요인을 전부 제거**. 원문에 "러닝 준비 화면으로 이동한다" 한 줄만 있던 구간
- **구성요소**
  - 코스 미니맵 + 이름/거리
  - **GPS 신호 강도 인디케이터** (약함/보통/좋음) — 약함일 때 [잠시만 기다려주세요] 표시 후 자동 갱신
  - 체크리스트 (미충족 항목만 노출)
    - `백그라운드 위치 권한` [허용하기]
    - `배터리 최적화 제외` [설정하기] + 제조사별 가이드
    - `배터리 잔량 15% 미만` 경고
    - `저장공간 부족` 경고
  - 옵션 토글: 음성 안내 / 진동 안내 / 자동 일시정지 / 화면 항상 켜기
  - **Safety Share 원터치 토글** — `가족에게 달리기 시작 알리기` (S-64에서 사전 등록된 대상)
- **액션**: [3초 카운트다운 후 시작] — 즉시 시작 금지(오작동 방지), 카운트다운 중 취소 가능
- **상태**: GPS 신호 '약함'에서도 시작은 허용하되 `기록이 부정확할 수 있어요` 경고 후 진행
- **예외**: 실내(GPS 미확보 60초) → `밖으로 나가면 자동으로 잡혀요` 안내 유지, 강제 차단 금지
- 🚫 **광고 절대 금지 구간**
- 📊 `prerun_view`, `prerun_blocker(type)`, `run_start(route_id, mode, gps_quality)`

### S-21 Sketch Navigation (러닝 중) — 앱에서 가장 중요한 화면

- **설계 원칙**: 달리면서 본다 = **팔을 흔들며 0.5초 안에 읽혀야 함**. 폰트 크게, 요소 적게, 탭 타깃 크게
- **레이아웃 (3단)**

  | 영역 | 내용 |
  |---|---|
  | 상단 40% | 지도 — 계획 경로(회색 실선), 실제 GPS 트레이스(강조 컬러, 점점 채워짐), 현재 위치 마커, Start/Finish 핀, 진행 방향 콘 |
  | 중단 | **Sketch 진행률 링** (그림이 몇 % 채워졌는지) + 다음 안내 `120m 후 좌회전` |
  | 하단 | 거리(가장 큼) / 경과시간 / 현재 페이스 / 평균 페이스 |
  | 하단 고정 | [⏸ 일시정지] (큰 원형) |

- **핵심 보완 3가지**
  1. **진행률 링을 "거리"가 아니라 "그림 완성도"로 표시** — 이것이 달림의 정체성. 일반 러닝앱과 다른 유일한 시각 요소
  2. **음성 안내 스크립트 정의**(원문 "추후" → MVP1 필수): 턴 안내 200m/50m 2회, 1km마다 랩 요약, 이탈 즉시, 완주 시 `그림이 완성됐어요`
  3. **화면 잠금 모드** — 주머니 오작동 방지. 스와이프 해제
- **상태**
  - GPS 유실: 상단 노랑 배너 `GPS 신호를 찾는 중` + 트레이스 점선 처리. **기록은 계속**
  - 배터리 15% 이하: `절전 모드로 전환할까요?`(지도 렌더 중단, 기록만 유지)
  - 전화 수신/타 앱 전환: Foreground Service 알림에 거리·시간 실시간 표시
- 🚫 **광고·팝업·페이월 절대 금지**
- 📊 `run_tick(1분 간격 요약)`, `gps_lost(duration)`, `nav_voice_played(type)`

### S-22 일시정지 / 종료

- **구성요소**: [계속 달리기](Primary, 크게) / [달림 종료](Secondary) / 현재까지 요약
- **종료 확인**: `아직 그림의 62%만 완성됐어요. 정말 종료할까요?` + [계속] / [기록 남기고 종료]
- **핵심**: 종료를 **누르기 어렵게** 만들되(길게 누르기 or 2단계), 안전상 필요 시 즉시 종료 가능한 [긴급 종료]는 별도 제공
- 📊 `run_pause`, `run_finish_attempt(progress)`

### S-23 코스 이탈 안내

- **트리거**: 계획 경로에서 반경 60m 이상 15초 지속 이탈
- **구성요소**: 상단 시트 `코스에서 벗어났어요` + 최단 복귀 경로 지도 표시 + [복귀 안내 받기] / [자유롭게 달리기]
- **핵심 원칙(원문 유지·강화)**: `[자유롭게 달리기]` 선택 시 그림 완성 실패를 감수하고 기록은 계속. **안전 > 그림**
- **안전 확장**: 위험 판단(급격한 정지 5분 + 심야) 시 `괜찮으세요?` 확인 → 무응답 시 Safety Share 대상에게 알림 제안
- 📊 `route_deviation(distance, resolved)`

### S-24 완주 판정 (처리 화면)

- **구성요소**: GPS 트레이스가 그려지는 애니메이션 + `그림을 확인하는 중...`
- **처리 항목**: 이동거리 / Route Coverage / 주요 지점 통과 / GPS 품질 / Sketch Match / 비정상 속도 / Deviation 비율
- **판정 결과 분기**: COMPLETED / PARTIAL / ABORTED / **UNDER_REVIEW(부정행위 의심)** ← 신규
- **상태**: 업로드 실패 → `기록은 안전하게 저장됐어요. 연결되면 자동으로 올릴게요` (로컬 보관 + 재시도 큐)
- 📊 `run_judgement(status, match, coverage, reason)`

### S-25 달림 결과 (Run Result) — **최대 수익 지점**

- **구성요소 (스크롤 순서)**
  1. **GPS 그림** — 화면의 60%, 그려지는 애니메이션 1회 자동 재생
  2. 거리 / 시간 / 평균 페이스 (Nike Run Club 스타일 대형 타이포)
  3. `Sketch Match 92%` / `Route Completion 97%` 2개 지표
  4. **획득 항목**: INK, 배지, First Discoverer, 미션 진행
  5. 토글: `[실제 경로] / [계획+실제]`
  6. **액션 행**: [공유하기](Primary) / [굿즈로 만들기] 💰 / [리플레이] / [달림북 저장]
  7. 랩 기록, 고도, 페이스 그래프 (기본 접힘)
  8. 코스 평가 요청(태그 선택 3초 컷)
- **PARTIAL일 때**: `그림의 68%를 완성했어요` + [이 코스 다시 도전하기] — 실패를 재도전 훅으로 전환
- 💰 **핵심 수익 훅 배치**
  - `Sketch Match ≥ 85%` 이면서 첫 완주자 → **[이 작품 굿즈로 만들기]** 카드를 액션 행 최상단에 노출 (S-54)
  - 완주 **3회차·10회차** 유저에게만 결과 하단에 RUN+ 소개 카드 1회
  - 전면광고는 이 화면 **완전 종료 후**에만, 그리고 **PARTIAL/ABORTED 시엔 금지**(감정 상함)
- 📊 `result_view(status)`, `result_action_tap(action)`, `goods_cta_impression`

### S-26 공유 카드 편집 — **성장 루프의 유일한 지점**

- **구성요소**: 배경(지도·블러·단색·그라데이션), 비율(9:16 · 4:5 · 1:1), 표시 항목 토글(거리·시간·페이스·SketchMatch·날짜·지역·함께 달린 인원), GPS Trail 스킨 적용
- **원문 보완 — 반드시 추가할 것**
  1. 카드 하단에 **코스 딥링크 QR/숏링크** 자동 삽입 (`이 코스 달려보기`)
  2. 링크 유입자는 **앱 미설치 시 웹 미리보기 → 설치 → 해당 코스 상세로 직행**(Deferred Deep Link)
  3. 초대 성사 시 **양쪽 모두 INK 지급** (S-70과 연동)
- **상태**: 이미지 생성 실패 시 로컬 재시도 (원문대로 클라이언트 생성 유지)
- 📊 `share_card_export(ratio, bg)`, `share_link_click`, `share_install_attribution`

### S-27 Run Replay

- **구성요소**: 타임라인 스크러버, 배속(1x/2x/4x), 페이스 히트맵 컬러, 영상(mp4) 내보내기
- 💰 무료: 앱 내 재생 1회 / 영상 저장은 리워드 광고 or RUN+
- 📊 `replay_play`, `replay_export(method)`

## D. 소셜 세션 (S-30 ~ S-39)

> **콜드스타트 경고**: 이 영역은 지역 밀도 없이는 100% 실패합니다. MVP3 출시 시 **1개 거점(부산 대학가 등)에만 세션 탭을 노출**하고 나머지 지역은 숨기는 것을 권장합니다. 빈 세션 목록은 앱 전체 신뢰도를 깎습니다.

### S-30 세션 탐색

- **구성요소**: 지도 핀 / 리스트 토글, 필터(날짜·시간대·페이스·거리·초보환영·성별조건·러닝온도)
- **세션 카드**: 코스 그림 썸네일, 제목, 일시(D-day), `3/6명`, 목표 페이스, 호스트 아바타 + 러닝온도, 태그(`초보환영` `대화하면서`)
- **상태(빈)**: `이 지역엔 아직 모집 중인 달림이 없어요` + [내가 첫 세션 열기](Primary) + [알림 받기](지역 등록)
- 📊 `session_list_view(count)`, `session_empty_region`

### S-31 세션 생성 (호스트)

- **입력 항목**(원문 유지 + 보완): 제목, 코스, 날짜/시간, 목표 페이스, 최소/최대 인원, 러닝 스타일 4종, 초보 환영, 최소 러닝온도, 참가 성별 조건 4종, 설명, **집결 장소(지도 핀 + 상세 설명)**, **우천 시 정책**(신규: 진행/취소/판단 후 공지)
- **가이드**: 최소 러닝온도를 높게 잡으면 `참가자가 줄어들 수 있어요` 실시간 힌트
- **핵심 보완**: 신규 유저(완주 0회)는 세션 생성 불가 → `한 번이라도 달려본 뒤 열 수 있어요`. 노쇼 호스트 억제 장치
- 📊 `session_create(pace, max, conditions)`

### S-32 세션 상세

- **구성요소**: 코스 미리보기, 일시/집결지(**승인 전에는 `부산대학교 인근`처럼 대략만**), 호스트 프로필 카드(러닝온도·참석률·소셜달림 횟수·행동 태그), 참가자 아바타 목록, 상태 뱃지(RECRUITING / NEAR_CONFIRMATION `성사까지 2명` / CONFIRMED …)
- **참가 조건 미충족 시**: 버튼 비활성 + 사유 표기 — 단 **성별 조건은 사유를 노출하지 않음**(`참가 조건이 맞지 않아요`로 일반화). 성별 역추론 방지
- **액션**: [참가 신청] / [공유] / [신고]
- 📊 `session_detail_view`, `session_join_blocked(reason)`

### S-33 참가 신청

- **구성요소**: 호스트에게 보내는 한 줄 메시지(선택), 내 프로필 미리보기(호스트가 보게 될 정보 그대로 표시 — **투명성 확보**), [신청하기]
- **상태**: 신청 후 `호스트가 확인 중이에요` + 예상 응답 시간, 취소 가능
- **보완**: 동일 시간대 중복 신청 방지, 신청 후 24시간 무응답 시 자동 만료 + 다른 세션 추천

### S-34 호스트 — 신청자 관리

- **표시**: 닉네임, 아바타, 러닝온도, 참석률, 소셜 달림 횟수, 편안한 페이스, 러닝 경험, 긍정 행동 태그, 과거 동반 여부
- **비표시**: 성별, 나이, 연락처 (원문 유지)
- **액션**: [승인] / 대기 유지 / 정원 충족 시 자동 `모집 완료`
- **보완**: 거절 대신 **무응답 만료** 구조 유지하되, 호스트에게 `24시간 내 응답률`을 프로필 지표로 표시해 방치 억제
- 📊 `host_approve(latency)`, `host_no_response_expire`

### S-35 팀 채팅

- **구성요소**: 텍스트, 이모지, 호스트 공지(상단 고정), 집결 위치 카드(지도), Quick Message 4종(`도착했어요` `가는 중이에요` `5분 늦어요` `오늘 참가 어려워요`)
- **보완**: `오늘 참가 어려워요` 선택 시 **취소 사유 선택 → 러닝온도 반영 로직 연결**(직전 취소 반복 시 감점)
- **생명주기**: 세션 종료 +24시간 후 읽기 전용, +7일 후 접근 종료
- **안전**: 각 메시지 롱프레스 → 신고. 1:1 DM 미제공(원문 방향 유지 — 안전상 옳은 선택)

### S-36 GPS 체크인

- **조건**: 시작 30분 전 ~ 시작 15분 후, 집결지 반경 150m 이내
- **구성요소**: 원형 진행 UI + 거리 표시(`집결지까지 80m`), [체크인] 버튼은 반경 내에서만 활성
- **상태**: WAITING / CHECKED_IN / LATE / NO_SHOW
- **예외**: GPS 오차·실내 집결(카페 등) 대비 **호스트 수동 확인 버튼** 필수 (원문 "필요하면"을 **필수**로 상향 — 오판정은 러닝온도 하락으로 직결되어 분쟁 유발)
- 🚫 광고 금지
- 📊 `checkin(status, distance_error)`

### S-37 Ready Check

- **구성요소**: 참가자 리스트 + 준비 상태, 호스트만 [달림 시작] 활성
- **보완**: 미체크인 인원 있어도 호스트가 시작 가능(대기 강제 금지), 시작 시 미체크인자는 자동 NO_SHOW 후보 → 사후 이의제기 가능

### S-38 세션 종료 후 평가

- **구성요소**: 체크인한 참가자만 노출, **긍정 행동 태그만 선택**(별점 없음 — 원문 원칙 유지), 스킵 가능
- **보완**: 태그 선택은 최대 3개, 미선택도 허용. **부정 평가는 태그가 아니라 신고 경로로만** 처리(태그로 부정 평가를 만들면 보복 평가가 시작됨)
- **바로 다음**: `다시 같이 뛰고 싶어요` 체크 → 상호 선택 시 Running Mate 성립
- 📊 `feedback_submit(tags)`, `mate_request`

### S-39 Running Mate

- **구성요소**: 메이트 목록(아바타, 함께 달린 횟수, 마지막 달림), [세션 열고 알리기]
- **보완**: 팔로우가 아닌 **상호 동의 기반**이므로 해제는 조용히(상대 알림 없음)

## E. 수집 & 성장 (S-40 ~ S-46)

### S-40 달림북 (Collection Grid) — **재방문 동기의 핵심**

- **구성요소**: 2열 그리드, 각 카드 = **실제 GPS 트레이스 썸네일**(제네릭 아이콘 절대 금지 — 원문 원칙 유지)
- **상단**: 총 작품 수 / 총 거리 / 이번 달 수집 수, 필터(전체·지역·시즌·미완성)
- **핵심 보완 — "빈 슬롯"**: 아직 안 달린 코스를 **실루엣 슬롯**으로 노출 (`? 🐳` 형태)
  → 수집형 게임의 핵심은 **빈칸이 보이는 것**입니다. 원문에는 채워진 것만 있고 빈칸이 없어 수집 동기가 약합니다.
- **상태(빈)**: 첫 작품 슬롯 1개만 크게 + `첫 그림을 완성해보세요`
- 📊 `dallimbook_view(owned, total)`, `empty_slot_tap(route_id)`

### S-41 작품 상세

- **구성요소**: GPS 그림 대형 뷰(핀치 줌), 달린 날짜/거리/시간/페이스/Match, 함께 달린 사람, [리플레이] [공유] [다시 달리기] **[굿즈로 만들기]** 💰
- **보완**: 같은 코스 여러 번 달린 경우 **베스트 기록 + 이력 리스트** 동시 표시(Route 1 : Run N 관계 시각화)

### S-42 컬렉션 (지역 / 시즌)

- **구성요소**: `부산 12/30`, `Halloween 3/5` 진행률 카드, 완성 시 **컬렉션 전용 배지 + 프레임** 지급
- 💰 시즌 컬렉션 완주자에게 **한정 굿즈 판매**(시즌 포스터 세트) — 희소성 기반 커머스
- **보완**: 지역 컬렉션은 **여행·관광과 직결** → PART 5의 B2B 지자체 상품과 동일 자산

> ⚠️ **주의(달림 프로젝트 실제 구현과 ID 충돌)**: 실제 구현에서 `S-42`는 이미 "마이" 탭(`docs/01-feature-spec.md` §1.5)으로 배정되어 있다. 이 문서의 컬렉션 화면을 실제로 구현할 때는 **`S-42`를 재사용하지 말고 새 번호(예: S-90대 또는 미사용 번호)를 `docs/01-feature-spec.md`에서 채번**한다.

### S-43 배지 / S-44 미션

## H. 대회(마라톤) 캘린더 & 러닝 커리어 (S-80 ~ S-86) — v1.1 신규

> **왜 이게 달림에 맞는가**
> 달림의 약점은 "달릴 이유가 그림밖에 없다"는 것입니다. 그림은 **처음엔 강력하지만 목표가 되진 못합니다.**
> 반면 대회는 러너에게 가장 강력한 목표이고, 이미 존재하는 수요입니다. 둘을 붙이면 이렇게 됩니다.
>
> ```text
> 목표(대회 D-day)  →  훈련해야 할 이유
>          ↓
> 훈련이 지루함     →  그림 코스로 달림  ← 달림의 존재 이유
>          ↓
> 완주             →  메달 선반에 기록 축적
> ```
>
> 즉 **대회는 "왜 달리는가", 그림은 "어떻게 즐겁게 달리는가"** 를 담당합니다. 역할이 겹치지 않습니다.

### S-80 대회 캘린더

- **진입**: 탐색 탭 `[대회]` 세그먼트 / 홈 D-day 스트립 / 외부 검색 유입(웹)
- **구성요소**
  - 뷰 토글: `리스트` / `월별 캘린더`
  - 필터: 지역(서울·경기 시군구), 종목(5K·10K·하프·풀·울트라·트레일), 접수 상태(접수중·접수예정·마감), 기간, 참가비
  - 대회 카드: 대회명 / **D-day** / 날짜 / 장소 / 종목 배지 / 접수 상태 칩 / 참가비 범위 / `달림 러너 12명 참가 예정`
  - 기본 정렬: 임박순 (접수 마감 임박 우선 = 행동을 만드는 정렬)
- **상태**
  - 빈: `이 조건에 맞는 대회가 없어요` + 필터 완화 제안 / 반경 확대
  - **데이터 신뢰 표기 필수**: 카드 하단 `3일 전 확인` + `정보가 다른가요? 신고`
- **데이터 운영 (현실적으로 가장 중요)**
  - 초기엔 자동 크롤링에 의존하지 말고 **수동 큐레이션 + 주 1회 갱신 배치**로 시작
  - 서울·경기 한정이면 **연간 대회 수가 관리 가능한 규모**이므로 1인 운영으로도 충분
  - 정확도가 곧 신뢰이므로 **"많이"보다 "틀리지 않게"**
- 💰 상단 `추천 대회` 슬롯 = 주최측 유상 노출 상품 / 접수 페이지 이동은 제휴 추적 링크
- 📊 `race_list_view(filters)`, `race_card_tap(race_id)`, `race_data_report`

### S-81 대회 상세

- **구성요소**
  - 헤더: 대회명, D-day, 포스터/대표 이미지
  - 개요: 일시, 집결 장소, **종목별(거리·참가비·정원·컷오프)** 표, 접수 기간, 기념품, 주최
  - 코스: 공개 코스가 있으면 지도 표시 + **[이 코스 미리 달리기]** (S-85)
  - 액션: **[내 대회에 담기]**(Primary, D-day 시작) / [접수하러 가기](외부 링크) / [공유]

- **완주 시**: `서울 하프 코스 30% 답사 완료` 진행률 누적 → 대회 D-day 카드에 표시

### S-86 대회 목표 훈련 플랜 (RUN+ 💰)

- **구성**: D-day 역산 주차별 플랜 — 주간 목표 거리, 롱런 1회, 인터벌/템포 1회, 휴식
- **차별점**: 플랜의 각 세션에 **달림 그림 코스를 자동 배정**
  ```text
  이번 주 롱런 12km  →  🐋 고래 코스 (12.3km, 한강)
  템포런 5km        →  ⚡ 번개 코스 (5.1km, 평지·신호 적음)
  ```
  → "훈련 플랜을 그림으로 달린다"는 조합은 다른 어떤 러닝앱도 제공하지 못합니다

- 📊 `plan_generate(race, weeks)`, `plan_workout_complete`

# PART 5. 서비스 지역 전략 — 서울·경기 한정 출시 (v1.1 전면 개정)

## 5.1 왜 지역을 좁히는 게 맞는가

달림은 **로컬 서비스**입니다. 전국 출시는 모든 지역을 텅 빈 상태로 만듭니다. 서울·경기로 좁히는 판단은 옳고, 이유는 3가지입니다.

1. **소셜 세션은 밀도 없이는 100% 실패합니다.** 참가자 2명이 모이지 않는 세션 목록은 앱 전체 신뢰도를 깎습니다.
2. **코스 품질을 사람이 검증할 수 있는 범위**여야 합니다. 첫 경험의 품질이 전부이고, 초기 30~50개 코스는 직접 달려보고 검증해야 합니다.
3. **대회 데이터 운영이 가능한 규모**가 됩니다(S-80). 전국 대회를 정확하게 유지하는 건 1인 운영으로 불가능합니다.

## 5.2 "서울·경기"도 여전히 넓습니다 — 거주지 기준으로 1차 코어를 좁히세요

수도권 인구는 2,600만 규모입니다. 이건 좁힌 게 아닙니다. **실제로는 3~4개 벨트로 시작**하는 걸 권장하며, 그중 최소 1곳은 **직접 거주하는 지역**이어야 합니다.

> 1인 개발에서 코스 30~50개를 "직접 달려보고 검증"하려면, 그 지역에 실제로 살아야 물리적으로 가능합니다. 세션도 초기엔 본인이 직접 호스팅해야 밀도가 생기므로 원거리 지역을 1순위로 잡으면 실행 자체가 막힙니다.

**거주지: 경기 남부, 수원 이북(수원·그 이남 제외)** 기준으로 벨트를 다시 잡으면 —

| 우선순위 | 지역 | 선정 이유 |
|---|---|---|
| **1** | **거주지 벨트 — 안양·군포·의왕·과천(+ 성남 분당·판교)** | 안양천·학의천·탄천 러닝로가 이어져 있고, 분당·판교는 계획도시 격자망이라 GPS 그림에 유리. **직접 답사·검증이 가능한 유일한 1순위 지역** — 초기 코스 50개는 사실상 여기서 나와야 함 |
| **2** | **한강 러닝 벨트** (여의도·반포·뚝섬·잠실·난지) | 러닝 인구 밀도 국내 최상, 접근성·안전(가로등·인적) 우수. 거주지에서 지하철/차로 접근 가능한 확장 벨트로 2순위 |
| **3** | **경기 신도시 확장 벨트** (위례·일산·**광교·동탄**) | 계획도시 격자망이라 그림에 유리. 거주지보다 원거리라 1순위는 아니지만, **분당·판교 벨트와 같은 "신도시 유형"으로 묶어 한 세트로 확장**하면 코스 제작 노하우(격자망 대응 패턴)를 그대로 재사용할 수 있음 |
| 4 | 대형 공원·호수 (안양 삼성산·의왕 백운호수·광교호수·일산호수·서울숲) | 루프 코스 형성 쉬움, 안전 |

> **여기서 가장 중요한 기술적 인사이트**: 달림의 코스 품질은 **도로망 형태에 종속**됩니다.
> 계획도시(신도시)와 하천변 산책로는 그림이 잘 나오고, 굽은 구도심 골목은 잘 안 나옵니다.
> 즉 **"어느 지역을 여느냐"가 AI Discovery 성능보다 결과 품질에 더 큰 영향을 줍니다.** 지역 선정은 마케팅 결정이 아니라 제품 결정이고, 여기에 **"직접 갈 수 있는가"** 라는 실행 제약이 하나 더 붙습니다.
>
> **광교·동탄 처리**: 거주지(수원 이북)보다 남쪽이라 초기 코스 직접 검증엔 불리하지만, **분당·판교와 같은 "신도시 벨트" 세트로 묶어두면** 1순위 벨트에서 검증한 신도시 코스 제작 패턴(격자망 루프 생성 규칙)을 그대로 적용해 확장 속도를 낼 수 있습니다. 그래서 완전히 배제하지 않고 **3순위 확장 세트**로 유지합니다.

| 기능 | 서울·경기 | 그 외 지역 |
|---|---|---|
| 혼자 달리기 · GPS 기록 · 달림북 | ✅ | ✅ **전국 허용** |
| 직접 그리기 → 코스 변환 | ✅ | ✅ 허용 |
| AI Discovery | ✅ | ⚠️ 허용하되 `이 지역은 아직 정확도가 낮아요` 고지 |
| 큐레이션 코스 · 지역 컬렉션 | ✅ | ❌ 미노출 |
| 소셜 세션 | ✅ | ❌ **탭 자체를 숨김** + [내 지역 오픈 요청] |
| 대회 캘린더 | ✅ | ❌ 미노출(2차 확장 시 오픈) |

- **[내 지역 오픈 요청]** 은 단순 버튼이 아니라 **확장 우선순위 데이터**입니다. 요청 수가 임계치를 넘은 도시부터 여는 방식으로 3차 확장 순서를 정하세요.
- 지역 오픈 시 대기 등록자에게 푸시 → **오픈 첫날 밀도를 인위적으로 만드는 유일한 방법**입니다.

## 5.4 확장 로드맵

```text
1차  거주지 벨트(안양·군포·의왕·과천·분당/판교) + 한강 벨트     코스 50개 직접 검증, 세션 오픈
2차  경기 신도시 확장 벨트(위례·일산·광교·동탄) + 서울 전역     대회 캘린더 수도권 전체
3차  요청 수 상위 도시(부산·대전·대구…)
```

## 5.5 초기 유입 채널 (마케팅 관점)

| 채널 | 이유 |
|---|---|
| 인스타/스레드 릴스 — GPS 그림 완성 타임랩스 | 이 서비스는 **결과물 자체가 콘텐츠**. 광고비 없이 확산 가능한 유일한 자산 |
| **대회 정보 웹페이지 (SEO)** ⭐ v1.1 | `서울 마라톤 일정`, `수도권 하프 대회` 검색 수요는 크고 꾸준합니다. 대회 캘린더를 **웹으로도 공개**해 유입 → 앱 설치로 전환. 앱 기능이 아니라 **획득 채널**로 봐야 하는 기능 |
| 대학 러닝 동아리·러닝 크루 제휴 | 밀도 확보 + 세션 초기 채우기 |
| 지자체 관광과·시설관리공단 제안 | S-55 B2B 파이프라인 시작점 (한강사업본부, 신도시 지자체) |
| 러닝 커뮤니티(당근 모임·네이버 카페) | 세션 호스트 확보 |

## 5.6 "그림"의 시즌 활용

크리스마스 트리, 하트(발렌타인), 벚꽃, 눈사람 — **시즌마다 새 이유**를 만들 수 있는 구조입니다. 이건 일반 러닝앱이 절대 못 하는 리텐션 장치이므로, 시즌 컬렉션(S-42)을 P2가 아니라 **P1로 올리는 것을 권장**합니다.

# PART 8. 재정렬된 개발 로드맵

원문의 순서(1~20)는 타당합니다. 다만 **수익·안전·성장 요소의 위치만 조정**을 권장합니다.

| 원문 | 조정 | 이유 |
|---|---|---|
| 수익화 = MVP5 | **굿즈(S-54) CTA는 MVP1 결과화면에 배치** | 결제는 안 붙여도 됨. **CTA 클릭률만 먼저 측정**하면 수익 모델 검증 완료 |
| 공유카드 = 후순위 | **MVP1 필수** | 유일한 무료 유입 채널 |
| 시즌 컬렉션 = P2 | **P1** | 계절마다 재방문 이유 생성 |
| 온보딩 = 없음 | **MVP1 최우선** | 첫 달림 전환율이 전부 |
| 치팅 방지 = 없음 | **MVP1에 걸음수 수집만이라도** | 나중엔 소급 불가 |
| Kakao 로그인 = 추후 | **MVP1** | 국내 가입 이탈 방지 |
| 세션 = MVP3 | 유지 + **한강 벨트 한정 노출** | 밀도 없는 소셜은 독 |
| **대회 캘린더 (v1.1)** | **MVP2** | 개발 난이도는 낮고(핵심은 데이터 운영), 유입·리텐션 효과는 큼 |
| **러닝 커리어/메달 선반 (v1.1)** | **MVP1(온보딩 S-04b)** | 경력 러너 이탈 방지. 나중에 넣으면 이미 떠난 뒤 |
| **대회 코스 미리 달리기 (v1.1)** | MVP3 | B2B 영업의 실물 레퍼런스가 되는 기능 |
