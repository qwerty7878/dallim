## 1. 컬러 시스템

### 1.1 결정 배경 (왜 이 색인가)

국내 대형 앱들이 이미 점유한 색을 확인한 결과:

| 색 | 선점 브랜드 |
|---|---|
| 초록 | 네이버 |
| 노랑 | 카카오 |
| 파랑 | 토스 |
| 오렌지/코랄 | 당근·직방·**Strava(러닝앱 카테고리 자체)** |
| 민트 | 배달의민족 |
| 핑크 | 야놀자 |
| 빨강 | 여기어때 |
| 보라(플럼 계열) | 마켓컬리("컬리퍼플") |

→ 순수 단색으로는 빈 자리가 거의 없어서, **단일 컬러 대신 시그니처 그라디언트**로 방향을 잡음. 달림은 애초에 "GPS 선이 브랜드의 본체"인 서비스라 그라디언트가 오히려 정체성에 더 맞음.

### 1.2 확정 컬러

```
Primary            #4A3AFF   블루바이올렛 — 컬리퍼플(플럼/자주 계열)과 구분되도록 파랑 쪽으로 튼 톤
Primary Dark        #2E22C7   다크모드 / 러닝 중 화면(S-21)
Primary Light       #EAE8FF   배경 강조, 선택 상태

Gradient Start       #4A3AFF   (블루바이올렛 — 그라디언트 시작)
Gradient End         #FF6B4A   (코랄 — 그라디언트 끝)
```

**그라디언트 적용 범위 (중요 — 아무데나 쓰지 않음)**

| 적용 O | 적용 X — 단일 Primary만 |
|---|---|
| GPS 궤적 자체(시작=보라 → 완성=코랄로 번지는 표현) | 버튼, 텍스트 링크, 아이콘 |
| 앱 아이콘 | 폼 요소, 인풋 필드 |
| 결과 화면(S-25) GPS 그림 | 리스트 아이템 |
| 온보딩 캐러셀 슬라이드 일러스트 | 탭바 |
| 공유 카드(S-26) 배경 옵션 중 하나 | 에러/경고 상태 색 |

→ **기능적 UI는 단일 Primary(#4A3AFF)로 일관성 유지, 감정적 순간(완주·공유·앱 아이콘)에만 그라디언트.**

**스플래시(S-00) — 2026-08-25 결정 변경**: 화면 전체를 그라디언트로 채우고 "달림" 텍스트를 띄우는 방식은 폐기. 배민·토스 등 국내 앱 관례를 따라 **Background(#FAFAF8) 단색 배경 위에 앱 아이콘(그라디언트 마크)만 중앙에 짧게 노출**하는 방식으로 변경. 그라디언트는 여전히 앱 아이콘 자체에는 쓰이지만, 화면 배경 전체에는 쓰지 않는다.

**앱 아이콘 모티프 — 2026-09-03 결정 변경**: 기존에는 "GPS 선이 브랜드의 본체"라는 컨셉을 그대로 단순 GPS 궤적 곡선(S자형 베지어 커브) 하나로 표현했음. 배민·토스처럼 좀 더 시그니처감 있는 아이콘을 만들기 위해, 모티프를 **러닝화 실루엣 + 위치 핀(location pin)** 조합으로 교체. 적용 대상은 런처 아이콘(`ic_launcher_background.xml`/`ic_launcher_foreground.xml`)과 스플래시 마크(`DallimMark`) 두 곳으로 한정하며, 다른 화면의 GPS 궤적 표현(결과 화면 GPS 그림, `RouteThumbnailView` 등 실제 GPS 데이터 렌더링)에는 영향을 주지 않는다. 그라디언트 컬러 값(Gradient Start #4A3AFF → Gradient End #FF6B4A)은 그대로 유지 — 참고 스크린샷은 단색 블루지만, 순수 블루는 토스가 이미 선점했다는 기존 색상 결정 근거(1.1절)를 지키기 위해 블루로 바꾸지 않았다.

같은 날 두 차례 더 다듬었음(사용자 실사용 피드백 기반):
1. **1차(채움 실루엣)**: 러닝화+핀을 흰색 단색 채움 실루엣으로 그려 브랜드 그라디언트 배경 사각형 위에 얹음. 에뮬레이터로 확인하니 외곽선만으로는 "신발"이라는 형태 정보량이 부족해 달팽이/비니 모자처럼 보임.
2. **2차(라인아트 + 흰 배경) — 최종**: "신발이 안 예쁘다, 배경은 흰색이 낫다, 색은 외형에만 써라, 신발 모양이 뚜렷하게 보였으면 좋겠다"는 피드백을 받아 배경을 흰색(`ic_launcher_background.xml` 단색 `#FFFFFF`)으로 바꾸고, 전경을 흰색 채움 실루엣 대신 **그라디언트 라인아트(스트로크)**로 전환. 흰 배경 위에서는 선 하나하나가 대비되어 훨씬 많은 디테일을 담을 수 있어, 뾰족한 발끝 + 세운 힐 카운터 + 텅(tongue) 이중 봉우리 실루엣 + 레이스 스티치 3개 + 아웃솔 안쪽 심선 + 힐 풀탭 고리까지 넣어 "러닝화/운동화"라는 형태를 뚜렷하게 살림. 핀은 힐 카운터 위에 살짝 겹치는 구도.

**adaptive-icon 세이프존 관련 함정**: 참고 스크린샷은 마스킹 없는 평범한 정사각형 이미지라 코너까지 채워도 되지만, 런처 아이콘은 시스템이 실제로 원형 마스크를 씌운다. 처음 낸 라인아트 버전(0.95 스케일, 모션 라인 포함)을 이론 계산만으로 세이프존(중심 54,54 반지름 33dp 원) 안에 들어온다고 판단하고 실기기 확인 없이 넘어갔다가, 실제 에뮬레이터 런처에 설치해보니 핀 전체와 발끝/모션 라인이 잘려나가는 것을 발견 — 이후 반드시 실기기(에뮬레이터) 스크린샷으로 재확인하는 것으로 프로세스를 굳혔다. 최종적으로 런처 아이콘에서는 모션 라인을 빼고 핀을 힐 쪽으로 당겨 축소한 뒤 전체를 0.67 스케일로 재배치해 세이프존에 맞췄고, 마스킹되지 않는 스플래시 마크(`DallimMark`)는 모션 라인 포함 원본 밀도 그대로 사용한다 — 두 에셋은 더 이상 좌표가 100% 동일하지 않다.

- 명암비 **4.5:1 이상**

## 3. 컴포넌트 규칙

### 3.1 카드
- 라운드: **20px**
- 그림자: 소프트 섀도우 (Elevation 낮게, `y:2 blur:12 opacity:0.06`)
- Material 3 기본 컴포넌트 그대로 쓰지 말고 커스텀 (기본 Material 느낌이 나면 브랜드감이 죽음)

### 3.2 GPS 실루엣 썸네일 (`RouteThumbnailView`)
- **모든 코스 카드에 필수** — 제네릭 아이콘·클립아트 절대 금지 (원문 원칙, 가장 중요한 규칙)
- 서버가 내려주는 GeoJSON LineString을 Canvas로 렌더링
- 배경: Primary Light(#EAE8FF) 위에 점 그리드(6x6, Primary 35% 알파, 2026-09-26 추가), 선:
  Primary(#4A3AFF) 또는 그라디언트
- 정사각형 비율 고정, 자동 bounding-box 계산 후 여백 15% 패딩
- **2026-09-26 점 그리드 추가**: 실사용 피드백("코스 카드가 모양만 있고 뒤에 배경이 아무것도
  없어 밋밋하다")으로 단색 배경 위에 선 하나만 있으면 "지도 위의 경로"가 아니라 "빈 칠판 위의
  낙서"처럼 보인다는 문제를 발견. 실제 지도 타일 없이도 위치감을 주기 위해 항상 켜져 있는 점
  그리드를 배경에 깐다(경로가 없는 빈 상태에도 그린다). 처음엔 14% 알파로 넣었는데 실기기에서
  거의 안 보인다는 재피드백을 받아 35%로 올림 — 점 그리드는 "은은한 텍스처"가 아니라 눈에 띄게
  보여야 "배경이 비어있지 않다"는 인상을 준다. 그라디언트가 아니라 기존 Primary 색의 텍스처라
  "그라디언트는 4곳에만" 규칙과 무관하고, 아이콘도 아니라 "제네릭 아이콘 금지" 규칙과도 무관하다.

- **2026-10-04 실제 지도 스냅샷으로 교체 (사용자 요청 — "미리보기가 AI 티가 난다")**: 앱이 네이버 지도
  키를 가진 빌드(`BuildConfig.NAVER_MAP_CLIENT_ID_CONFIGURED`)에서는 `RouteThumbnailView`가 실제 네이버
  지도 위에 경로(Primary 선 + 흰 외곽선, 시작=흰 점, 도착=코랄 점)를 올린 정적 이미지를 쓴다. 위 점 그리드
  Canvas 실루엣은 (a) 스냅샷이 캐시되기 전 첫 로딩, (b) 오프라인/10초 내 렌더 실패, (c) 키 없는 빌드/프리뷰의
  **폴백**으로 남는다 — 규칙("모든 코스 카드에 썸네일 필수, 제네릭 아이콘 금지")은 그대로다.
  구현 `core-ui/.../MapSnapshotThumbnail.kt`: 화면 밖 `MapView`를 열어 `takeSnapshot`으로 찍고
  (동시 2개 제한) 메모리 LRU 24MB + 디스크(`cacheDir/route-map-thumbs`) 캐시. 캐시 키는 경로 좌표+렌더
  해상도(480/640px 두 버킷)+스타일 버전이라 같은 코스는 어느 화면에서든 한 번만 렌더한다. 작게 표시하는
  썸네일도 큰 해상도로 찍어 축소해 쓴다(지도 로고/라벨이 픽셀 고정이라 작게 직접 찍으면 로고가 화면을 덮는다).
  **네이버 로고는 약관상 제거할 수 없어 스냅샷에 그대로 남는다.** 지도 타일 호출은 코스당 기기별 최초 1회.

## 5. Compose 토큰화 가이드 (개발 시 참조)

```kotlin
object DallimColors {
    val Primary = Color(0xFF4A3AFF)
    val PrimaryDark = Color(0xFF2E22C7)
    val PrimaryLight = Color(0xFFEAE8FF)
    val GradientStart = Color(0xFF4A3AFF)
    val GradientEnd = Color(0xFFFF6B4A)

    val RouteDiscovery = Color(0xFF9E9E9E)
    val RouteVerified = Color(0xFF4A90D9)
    val RouteUnderReview = Color(0xFFF5A623)

    val Background = Color(0xFFFAFAF8)
    val BackgroundDark = Color(0xFF0F0F14)
    val TextPrimary = Color(0xFF1A1A1E)
    val TextSecondary = Color(0xFF6B6B75)
}

val DallimGradient = Brush.linearGradient(
    colors = listOf(DallimColors.GradientStart, DallimColors.GradientEnd)
)
```

> LOOP 0(프로젝트 기반)에서 `core-ui` 모듈에 위 토큰을 가장 먼저 세팅하고, 이후 모든 화면은 하드코딩된 색상값 없이 이 토큰만 참조하도록 한다.
